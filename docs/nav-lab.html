5 · Decisions to take
D1 Rec: adopt

Two-level IA: topic → drill

The left rail mirrors the routes’ first segment and the textbook’s chapters, kills the repeated set titles, and is the only structure that survives the catalog growing past translations (proofs, quantificational, inductive sets are all still to come).

D2 Rec: adopt

Sets Q + R merge under “Informal Logic”

Both already live under /informal/. Two top-level single-drill topics would make the rail lie about depth; one topic with two honest drills doesn’t.

D3 Decided 2026-08-14

Topic order: set letter

Malik’s call, reversing the lab’s initial lean. Set letters are the one reference everyone shares — syllabi assign “LogiCola Set N”, and the 2008 software taught the letters. Course order presumed the reader owns Gensler’s book; many users don’t. The toggle above frame 1 stays for the record.

D4 Rec: keep the kind prefix

Drill names: “Translations: Easy”, not bare “Easy”

Khan can label a row “3rd grade” because the row is the whole story. Our drills are links, and link text has to carry its purpose out of context (WCAG 2.4.4) — a screen reader’s link list full of “Easy / Hard / Basic” is noise. The prefix also matches the quiz page titles the click lands on.

D5 Decided 2026-08-14

Descriptions ship in the panel

Follows from D8. Master–detail has the room, and the catalog’s one-liners are the scent a first-week student needs — “syllogistic” means nothing on day one.

D6 Rec: keep visible

Set letters stay in the UI

Syllabi and Gensler’s own course materials assign work by set letter (“do LogiCola Set N”). The mono set tags in panel headers — and on drills only where a topic spans two sets — keep that lookup alive without letting letters lead the hierarchy. The rail stays clean — topics only.

D7 Narrowed: C3 · C4

Mobile: bottom sheet; drill-in or tiles inside

Malik (2026-08-14): the bottom sheet “might be the winner”, and of its contents “I like C3 and C4” — so accordion and half-detent fall away (kept live above), and the remaining call is drill-in vs launcher tiles, now judged in their branded forms in § 3d.

D8 Decided 2026-08-14

Desktop: master–detail (A); B rejected

Malik’s call: B shows everything, but thirteen bold links in three columns risks cognitive overload. A’s first scan is six topics; depth arrives only on demand — and it’s the structure that scales when proofs and quantificational sets land.

B stays interactive above (relabelled), because the judgement was made against the living thing and should be re-makeable.

D9 Rec: adopt

Mobile menu carries Blog + Donate

A gap this lab surfaced rather than a redesign goal: the phone navbar has no route to Blog or Donate at all. Both mobile variants add them as a sheet footer. Cheap, and Donate is the project’s oxygen.

D10 Decided 2026-08-14

Chapter numbers stay out of the UI

The chapter mapping justified the grouping, but as visible meta it assumed the reader owns the textbook — many users don’t, and for them “Chapter 12” is noise. Set + topic name carry orientation on their own. The mapping survives in the docs, not the menu.

Three candidates ride the decided shell: Brand · cream (the provisional green-on-cream), Set L (mint under plum, magenta accent), and Brand · original (the 2008 aqua + navy, extracted from Gensler’s own binaries). 6 · Accessibility model (release blocker, not garnish)

Keyboard map — desktop A

  • Tab reaches the trigger, then the active topic in the rail; ↑ ↓ move across topics (panel follows focus instantly — the 90 ms delay is pointer-only).
  • → or Tab enters the drill list; ↑ ↓ move between drills; ← returns to the owning topic.
  • Esc closes the panel and returns focus to the trigger. B needs none of this — it’s a plain link grid, which is itself an accessibility argument for it.

Flags for the port

  • The production menu keeps Radix NavigationMenu — this lab fakes its open/close and pointer grace; don’t hand-roll those in the app.
  • The trigger’s green #17a34a on white is ≈3.3:1 — it already fails 1.4.3 for 14 px text in production today. The brand pass must resolve it (darker green, or ink text with green reserved for larger weights). Resolved in the § 4 frames: the scheme’s type colour carries every small run of text; the coloured ink is display, underline and CTA ground only.
  • NEW gem and dot: the gem carries literal “NEW” text; the topic-row dot needs sr-only “new exercises inside” so the scent isn’t pointer-only. Colour is never the sole signal (1.4.1).
  • Grays used here (#6b7280 on white ≈4.8:1) pass AA for the sizes used; re-check every pairing after the brand pass recolours surfaces.
  • Reduced motion: the drill-in slide and caret spins collapse to cuts under prefers-reduced-motion — same rule the quiz bar follows.
7 · Port notes (after sign-off, not before)
  • Topics derive from slugs[0] of content/quiz-catalog.json — no second source of truth. Topic display metadata (name, blurb, order) is one new small content file.
  • Desktop stays inside the existing shadcn NavigationMenu; mobile accordion reuses ui/accordion (the FAQ’s type="multiple" precedent).
  • NEW badge propagation is derived: a topic is new while any drill in it has isNew.
  • The quiz route’s desktop navbar and the homepage share the same component — one port serves both. The gem badge ports via gemClip() from lib/pixel.ts, exactly as this lab renders it.
  • The § 4 brand frames spend only marketing-lab tokens — scheme roles (ground / ink / type), markSvg mirrored from public/logicola-wordmark.svg, the marketing CTA silhouette — and derive every muted tier through an ensure-contrast loop at render time. Port them as computed tokens, not baked hexes.
